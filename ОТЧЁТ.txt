1. КОРОТКО, О ЧЁМ ЭТО
=====================================================================
Локальная программа для одного компьютера, без интернета и без установки.
Ставится просто: кидаешь папку с файлами на комп учителя, запускаешь
python main.py — и всё. Ничего доустанавливать не надо, всё на стандартной
библиотеке Python (tkinter). Единственные необязательные допы — см. пункт 8.

Программа делает так, как мы договаривались:
 - главное меню (Новая игра / Настройки / История игр / Правила);
 - настройки: звук 0-10, вопросы, конфигурация баллов и времени, классы;
 - вопросы можно править прямо в окне, можно подтянуть из txt файла;
 - класс загружается из txt со списком фамилий и подписывается (например 10В);
 - перед игрой участников мышью раскидываем по командам, есть блок «отсутствуют»;
 - игра: колесо фортуны -> поле 8x8 -> вопрос с таймером -> раздача баллов -> снова;
 - в конце окно результатов, оно же пишется в историю игр.

3. main.py — ТОЧКА ВХОДА

// Шапка файла: точка входа, окно, масштаб, F11, реестр экранов.

Что тут есть:

SCREENS — словарь «какой экран каким классом рисуется». Если захочешь
добавить новый экран — пишешь класс, добавляешь строку в этот словарь и
вызываешь через app.show("имя").

class App — само окно программы. Внутри:

  __init__
      Ставит заголовок окна, читает настройки, выставляет громкость,
      грузит фон oboi.png (если он есть), собирает контейнер под экраны,
      ставит размер окна из настроек (по умолчанию 1080x1920), вешает
      F11 и Escape, и открывает главное меню.

  show(name, **kwargs)
      Главный переключатель. Убивает текущий экран, рисует новый.
      Через него ходит вся программа: app.show("game", session=session).

  set_window_size(w, h, remember=True)
      Ставит размер окна, центрирует его и пересчитывает масштаб.
      remember=True — ещё и запомнить размер в настройках.

  toggle_fullscreen(force=None)
      Это то, что на F11. overrideredirect + fullscreen, то есть окно
      во весь экран и вообще без рамки. Escape возвращает как было.

  set_ui_scale(value)
      Ручной множитель масштаба (кнопки «Мельче / Крупнее» в настройках).

  _apply_scale()
      Считает масштаб от размера окна: берём ширину/1080 и высоту/900,
      что меньше, то и берём, потом умножаем на ручной множитель.
      Полученное — во сколько раз увеличиваем шрифты и отступы.

  _rerender()
      Перерисовывает текущий экран под новый масштаб. Игру и экраны,
      где уже что-то наполнено (результаты, раскидка команд), специально
      не трогаем — иначе там потеряется состояние.

  _on_configure(event)
      Ловит, когда пользователь тянет край окна. Ждёт 250 мс (чтобы не
      перерисовывать на каждый пиксель) и вызывает _apply_scale.

  _load_background(name)
      Пробует открыть oboi.png через PIL (если установлен) и ужать его.
      Если PIL нет — открывает как есть средствами tkinter. Если файла нет
      вообще, возвращает None, и меню рисуется без фона, это нормально.

  register_drop(widget, callback)
      Вешает на виджет приём перетаскиваемых файлов. Работает только если
      установлен tkinterdnd2 — если его нет, возвращает False, и в окнах
      импорта просто появляется кнопка выбора файла.

  drop_paths(event)
      Разбирает то, что браузер/система прислала при перетаскивании,
      в список путей. Понимает и путь с пробелами в фигурных скобках.

main()
      Запуск. Если вдруг вылетит ошибка — она дописывается в crash.log
      рядом с программой, чтобы можно было показать и починить.

// Шапка файла: цвета палитры (рис.7), шрифты, кнопки, карточки, прокрутка.

PALETTE — все 21 цвет с рис.7, подписал как в оригинале. Один цвет в
картинке был с опечаткой (#9FC8A, пять знаков) — дописал ноль, получилось
#9FC8AA. Палитру держу тут как памятку, в интерфейсе использую C.

C — семантические цвета. Тут понятно, за что каждый отвечает:
  bg       фон окна, тёплый картон
  surface  фон карточек
  ink      основной текст и рамки
  accent   терракота — главная кнопка, корпус корабля
  orange   тревога (осталось мало времени)
  blc / easy / normal / hard / sphard — цвета сложностей, ими красятся
             клетки поля после выстрела и плашки в списках
  cell     цвет незакрытой клетки
  alert    красный, когда время вышло

set_scale / get_scale / px(v)
      px переводит «виртуальные» пиксели (у нас раскладка под 1080x1920)
      в реальные. Все размеры в программе идут через px().

f(size, weight, family)
      Шрифт с учётом масштаба. Один раз создаётся, кэшируется.
clear_fonts() — чистит кэш, вызывается при смене масштаба.

title() / text() / caps() / badge()
      Заголовок (Georgia), обычный текст (Segoe UI), мелкая подпись
      капслоком с трекингом (как подписи под чипами на рис.7) и цветная
      плашка.

class RoundButton
      Кнопка со скруглением и тенью, нарисована на Canvas. Умеет менять
      текст (set_text), команду (set_command), вид (set_kind) и
      включаться/выключаться (enable). Виды: primary, secondary, danger,
      ghost, chip, dark.
button() — просто обёртка над RoundButton.

card() — карточка с толстой рамкой. Возвращает (рамка, содержимое).

divider() — тонкая линия-разделитель.

class Scroller — прокручиваемая область. У него есть .body, внутрь
которого всё и кладётся. Колёсико мыши работает.

entry() / spinbox() — поля ввода в стиле оформления.

apply_styles(root) — стили ttk (выпадающие списки, полосы прокрутки,
слайдер звука).

// Шапка файла: всё, что программа помнит между запусками (папка data/).

data/settings.json  настройки
data/questions.json вопросы
data/classes.json   сохранённые классы
data/history.json   история игр

DEFAULT_SETTINGS — значения по умолчанию: звук 5, окно 1080x1920,
время по сложностям (3:30 / 2:20 / 1:40 / 1:00 / 0:30), баллы по
сложностям, штраф за списывание -10.

SEED_QUESTIONS — стартовый набор вопросов (26 штук), чтобы программа была
играбельной сразу, без возни с файлами. Их спокойно удалять и менять.

_ensure_dir / _read_json / _write_json
      Технические мелочи: создать папку, читать JSON (если файл битый или
      его нет — вернуть нормальное значение, а не упасть), писать JSON
      красиво и с русскими буквами.

load_settings() / save_settings()
      Настройки. При чтении недостающие поля добираются из DEFAULT_SETTINGS,
      так что после обновления программы старый settings.json не сломается.

load_questions() / save_questions() / add_questions()
      Вопросы. При самом первом запуске засевается SEED_QUESTIONS.
      add_questions дописывает новые в конец и сразу сохраняет.

load_classes() / save_classes() / add_class()
      Классы. add_class заодно чистит имя: «10 в» превратится в «10В».

read_class_file(path)
      Читает txt со списком участников (по одному человеку на строку),
      сам пробует кодировки utf-8 / cp1251 / utf-16.

suggest_class_name(path)
      Предлагает подпись класса из имени файла без расширения:
      «10V.txt» -> «10V». Именно то, что просил.

load_history() / append_history(entry) / clear_history()
      История игр. Новые игры вставляются в начало.
now_stamp() — «16.09.2026 17:30».

// Шапка файла: воспроизведение over.mp3 и прочих звуков.

set_volume / get_volume — громкость 0..10, тянется из настроек.
play(name) — главный вход: play("over"). Если файла нет — тихо пищит
динамиком, чтобы тишина не выглядела поломкой.
play_over() — короткий вызов для конца времени.
_find() — ищет sounds/имя.mp3 или .wav.
_play_file() — выбирает, чем играть: Windows — winmm (mciSendString),

не зависал.
_play_win() — конкретно проигрывание через winmm, там же крутится
громкость (у mci шкала 0-1000, поэтому volume*100).
_beep() — запасной писк.
stop_all() — заглушить всё.

// Шапка файла: модель вопроса, разбор файла, время/баллы, раскладка поля.

BASE_TIME   сколько секунд даётся: blc 30, easy 60, normal 100,
            hard 140, sphard 210.
LABELS      как сложность показывается на экране по-русски.
SHORT       короткая подпись для плашки (БЛИЦ, ЛЁГКАЯ и т.д.).
POINTS      сколько баллов стоит вопрос: 1 / 2 / 4 / 6 / 8.
            Тут я собрал пропорцию так: одна сложная (sphard = 8) равна
            четырём лёгким (4 x 2 = 8) и восьми блицам. Поменять можно
            в окне «Создание конфигурации», в код лезть не надо.
SHIP_SIZE   корабль -> сложность: 4 клетки -> easy, 2 -> normal, 1 -> hard.
SHIP_COUNT  сколько каких кораблей кладём (3 четырёхпалубника,
            4 двухпалубника, 5 однопалубников = 26 клеток из 64).
            Остальные клетки — вода, там блиц-вопросы.

norm_rarity(raw)   приводит «hard», «сложная», «HARD(bas)» к нашему ключу.
parse_time(raw)    «bas» -> базовое время, «03:40» -> 220 секунд.
fmt_time(sec)      220 -> «03:40».
time_for(q)        сколько секунд на конкретный вопрос (своё время важнее
                   базового).
points_for(q)      сколько баллов за конкретный вопрос.
make_question()    собирает словарь вопроса: текст, ответ, сложность, время.

parse_questions_text(text)
      Главный разборщик файла с вопросами. Строка живёт так:
      2. Какого цвета шишка Answ: "42" // Time: 03:40 // Rarity: hard
      Он срезает номер в начале, находит Answ:, всё до следующей метки
      (// Time: или // Rarity:) — это ответ, кавычки вокруг ответа срезает
      (они нужны только для чисел). Возвращает (вопросы, замечания) —
      замечания потом показываются в окне импорта, там видно, какие строки
      я пропустил и почему.
read_questions_file(path)
      Читает файл в одной из кодировок и зовёт parse_questions_text.

_free() / build_board()
      Раскладка кораблей на поле 8x8. Корабли не касаются друг друга —
      проверяется по всем восьми соседним клеткам. После раскладки каждой
      клетке выдаётся вопрос нужной сложности; если вопросов такой
      сложности не хватило, берётся любой оставшийся, а сложность клетки
      остаётся своя.
cell_index() / cell_name()
      Номер клетки 0-63 и её имя для ведущего («Г-4»).

// Шапка файла: список вопросов, окно добавления, импорт из файла, класс.

QuestionsScreen
      Список всех вопросов. Каждый — карточка с номером, сложностью,

      сохраняет базу. «Сохранить» — на всякий случай, хотя сохранение
      происходит и само.

QuestionDialog
      Маленькое окно: поле для вопроса (многострочное), поле для верного
      ответа, выбор сложности из списка, время (пусто = базовое).

ImportScreen
      Окно импорта вопросов из файла. Есть зона перетаскивания (пунктир

      Кнопка «Добавить N вопросов в базу» дописывает их в конец.

LoadClassScreen
      Загрузка класса: выбираем или перетаскиваем txt со списком,
      поле «как подписать класс» подставляется из имени файла (его можно
      поменять на 10В и т.п.), ниже — сетка с фио, чтобы глазами

// Шапка файла: колесо, поле 8x8, вопрос, таймер, выдача баллов.

Внутри GameScreen четыре фазы, они сменяют друг друга:

 1) wheel — колесо фортуны. Рисуется на Canvas: сектора на команды,
    стрелка сверху. Крутится 40 шагов по 30 мс с торможением (ease out),
    останавливается точно на выбранной команде. Выбор команды случайный,
    но делается ДО прокрутки — поэтому колесо честно докручивается до неё.

 2) board — поле 8x8. Слева цифры 1-8, сверху буквы А-З. Клетки
    нарисованы скруглёнными с зазором, чтобы не промахнуться мышью.
    Клик по клетке — выбор (клетка желтеет), кнопка «Подтвердить»
    справа снизу — выстрел. Повторно по открытой клетке выстрелить
    нельзя. Сверху видно, чей ход, какой раунд и счёт всех команд.

 3) question — вопрос. Сверху плашка сложности (по-русски), название
    клетки, подсказка «попадание в корабль — задача для всех команд»
    или «промах — блиц-вопрос». Справа таймер крупно: чёрный, за 30
    секунд оранжевый, за 10 красный. Когда время вышло — играет
    over.mp3, снизу появляется красная полоса «ВРЕМЯ ВЫШЛО».
    Кнопка «Показать ответ» — для ведущего. «Продолжить» — в раздачу
    баллов.

 4) score — раздача баллов. На каждую команду строка: имя, сколько уже
    набрано, поле ввода и быстрые кнопки (+3, +2, +1, +1, -1, -10 и
    балл за сложность). Внизу подпись: сколько даётся за верный ответ,
    +3/+2/+1 первым трём командам и +3 стрелявшей. Ниже — выбор, кто
    стреляет следующим (по умолчанию следующая по кругу, но можно
    поставить ту, кто ответил верно — как в правилах). «Продолжить»
    пишет баллы в лог раунда и открывает следующий ход.

Остальное в файле:
  _build_top / _update_top     верхняя полоса: чей ход, раунд, счёт
  _build_foot                  нижняя полоса под кнопки
  _draw_wheel / _spin          колесо и его анимация
  _draw_board / _board_click   поле и попадания мыши по клеткам
  _open_question               сборка экрана вопроса
  _update_timer / _tick        таймер
  _time_over                   что делать, когда время вышло
  _to_score / _apply_score     окно баллов и их запись
  _bump / _set_next / _paint_next  мелочи этого окна
  _sheet                       лист ответов (номер клетки, вопрос, ответ) —
                               ровно тот лист, который нужен командам,
                               чтобы донисать старые задачи
  _exit_button / _finish_click / _disarm
                               «Закончить досрочно» — нужно нажать ДВАЖДЫ,
                               через 4 секунды кнопка успокаивается обратно
  _finish                      запись игры в историю и переход к результатам

13. ФОРМАТ ФАЙЛА С ВОПРОСАМИ
=====================================================================
1. Какого цвета лось // Answ: Розовый // Time: bas // Rarity: easy
2. Какого цвета шишка Answ: "42" // Time: 03:40 // Rarity: hard
3. Кто самый крутой Answ: Я крутой  // Time: 02:10 // Rarity: normal

 - Номер в начале строки можно не ставить, программа и так поймёт.
 - Всё между «Answ:» и следующей меткой — верный ответ.
 - Числовой ответ пишем в кавычках, иначе его перепутать с временем.
 - Time: bas — базовое время сложности. Можно написать 03:40 или 220.
 - Rarity: sphard / hard / normal / easy / blc. Понимает и русские
   варианты (лёгкая, средняя, сложная, блиц).
 - Пустые строки и строки, начинающиеся с #, пропускаются.

ФОРМАТ ФАЙЛА С КЛАССОМ — просто по одному человеку на строку:
Артеменко Антон
Веселая Ольга
Гаврилова Полина
